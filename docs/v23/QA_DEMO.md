# Optional V2.3 durability corpus and version comparison

Settings -> Optional V2.3 durability demo data -> Load. Explicit only; no normal
first-run population. Namespace `demo.v23.*`; original synthetic assets, no user files.
Deterministic content definitions and step order; actual history revision IDs/timestamps
are generated by the unchanged history engine and are intentionally not hardcoded.
Loading an unchanged completed corpus is idempotent. Edited/colliding content or corrupt
asset collisions are retained and cause refusal, not overwriting.

Expected final authored version counts: Notebook 8; Article 5; Cheatsheet 4; QCM 4;
PDF 4; Notebook tree 5. Examples include block edits/reorders, canonical Article/QCM,
closed accepted/rejected/stale synthetic audits, two PDF byte variants, a historic-only
image and a shared image. Personal QCM attempt/reflection is separate from authored
QCM history; editing it creates no QCM revision. A pinned old bookmark and manual
reference exercise historical routing. Pending proposals are not auto-approved.

Safe cleanup removes only byte-equivalent known current demo projections and exact
unmodified synthetic personal entries. Edited or externally referenced demo content is
retained. Legacy links/related IDs, ReadingTargets, notes, attempts, bookmarks and tree
nodes protect references. Cleanup prunes only known unchanged demo tree nodes. It NEVER
deletes immutable history, audit or historical assets. Reinstall after customized cleanup
may be conservatively refused; use a separate disposable profile for repeatable QA.

## Version Compare contract
Select a resource's historical version -> Compare with current: A/left is selected old
revision, B/right is current head of the SAME stable logical resource. Prior active B
cannot invert the comparison. Version labels remain visible; existing Changes,
Side-by-side, A-only and B-only controls remain. Historical PDF identity includes exact
immutable byte provenance, never the current document's replacement bytes.

Archive descriptors preserve version entries with archive ownership. Missing bytes
produce an exact required archive ID/root, not fallback content. Attach exact file,
then archived/current or archived/archived comparison uses the same reader and semantic
diff. Restore-as-new appends a new live revision and retains exact restoredFromRevisionId.
Agent restore remains staged/reviewed; attachments never accept a proposal.

The History icon is a dedicated layered history/pages symbol; Read Later keeps its clock.
Accessible Version History labels are preserved. No reader redesign/new content type.
