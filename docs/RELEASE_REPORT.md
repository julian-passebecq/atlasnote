## Implemented reader behavior

**True Focus** removes top bar, both rails/sidebars, context panel, status, tabs, breadcrumbs, note/PDF controls and other persistent chrome from layout. Reading starts at viewport y=0 and fills its height. Only a small floating exit remains; Escape also exits. The browser Fullscreen API is not invoked. The DOM suite checks Continuous, Book, Parallel and Compare, exact semantic anchor state and restoration of prior sidebar preferences. Focus + Compare keeps both content panes and their divider even at narrow width.

**Compare** now opens an empty active content-picker pane without copying the first pane. The next tree/search/collection selection targets it. Toggle-off retains the active non-empty pane, its complete tab/history state, and the last split ratio. An empty active pane falls back to the non-empty peer. Pointer and keyboard resizing, independent tabs/modes/English/anchors, deliberate same-document reads and note/PDF combinations are exercised. Fresh tabs also start empty. Empty-history validation and cursor construction were corrected without resetting existing saved tabs.

**Book** still uses the original measured block-aware paginator, verified byte-for-byte against the supplied baseline. It displays consecutive same-note sheet pairs while scrolling vertically; sheet numbers are never canonical identity. Actual tests reconstruct paragraphs, code lines, table rows and list items without loss, retain real Mermaid SVG, honor breaks, avoid tested stranded headings and expose complete Continuous source for oversized unsplittable blocks. A small separate anchor helper adds source-unit/character-or-row offsets and viewport-relative restoration across reflow; the paginator was not replaced.

**Themes** retain persisted keys `fluent`, `neutral`, `academic`, now labelled Microsoft Fluent, Light Minimal and Medium / Paper. Navigation, tabs, reader canvas/sheets, cards, code, tables, callouts, context, PDF chrome, dialogs and menus use semantic surface/text/selection tokens. Computed main text/muted/accent contrasts meet 4.5:1 in the tested palettes; keyboard focus is visible. This bounded check is not a full-site accessibility certification.

## Mixed collections and private PDFs

Folder/notebook labels open a direct-child collection projected from the existing tree. Separate chevrons expand hierarchy. Cards distinguish notes/PDFs/folders and display summary, language, known PDF page count and enabled learning flag. All/Notes/PDFs, language, domain, technology and text filters work together; default tree order and title sort are supported. Normal/modifier/middle opens, new tabs, other pane, bookmark, rename, canonical move and archive are tested. A portal-based menu fixes stacking behind the context panel and restores keyboard focus to the initiating control.

Local intake offers file selection, arbitrary existing nested placement, a new target folder, title/summary, primary language, document type, domains, technologies, source/attribution and conservative rights. Unknown provenance/page counts are left blank rather than invented. Exact bytes are SHA-256 checked before commit; existing identical content is reused, not duplicated. The local editor exposes title, language and tags without JSON. Public availability does not imply redistribution rights: uncertain material stays private reference-only/unreviewed.

The production storage transaction code is unchanged. The DOM intake test uses an explicitly labelled in-memory commit adapter and Python SHA-256 bridge because about:blank lacks secure WebCrypto. Exact chosen bytes and metadata are verified at that boundary and in real backup ZIP round trips. **Actual production IndexedDB write/readback, reload and fresh-context restore remain BLOCKED**, rather than being claimed from this adapter.

## Private export/repository contract

The private template has one canonical `main`; optional short-lived `ingest/<batch>` branches are for review only. Topics remain tree placement and namespaced facets. Its actual Python builder emits a standard private Atlas workspace ZIP accepted by the application's actual `readWorkspace()`. It validates safe bounded paths/metadata, exact PDF bytes/hash, placement, visibility/rights and SHA duplicates; deterministic ZIP output and existing version/hash idempotence are tested. Missing/tampered/oversized assets fail closed.

Workspace settings also exports an existing private PDF collection as a standalone standard pack. It includes exact PDF bytes, PDF wrappers and required hierarchy, not public PDFs, teaching-note prose, personal remarks/flags/bookmarks, passwords or unrelated state. Private Document/Page/leaf IDs stay stable. When a local PDF is filed inside a built-in public notebook, only the **exported public context IDs** are deterministically remapped, with `atlas-placement-map.json`, preventing ownership collisions in a fresh workspace. The live workspace is never renamed.

This standalone export is not a bypass for source ownership conflicts and is not a full backup. Reimport into its original workspace may correctly conflict. Update original authored packs with the same original pack ID and higher version; use complete workspace backup/restore to transfer all personal/local state. The app does not authenticate to or directly synchronize a private repository.

## Offline PDF preparation

`tools/prepare-pdf.py` and the identical template helper are working authoring utilities, not browser dependencies. They perform signature/object safety inspection and structural lossless cleanup first. Explicit `study` uses approximately 220 -> 160 DPI/JPEG 82; explicit `compact` uses 180 -> 130/JPEG 75. Both require a render-QA directory. No whole-page rasterization or OCR is used. Every retained candidate must preserve page count, dimensions and per-page normalized selectable-text fingerprints; the original is kept when no candidate is smaller.

Machine-readable reports contain tool/engine versions, timestamp, profiles/options, source/candidate/result bytes and hashes, ratio, selectable-text presence/fingerprints, warnings and QA metrics. Duplicate hashes before or after preparation do not create another binary. Actual synthetic fixtures exercise non-PDF, encrypted/active content, image-only behavior, oversize policy and original retention. The operational warning remains above 12 MiB; the hard 20 MiB asset limit cannot be raised by a flag.

In the final run, the five-page lossless fixture decreased from **51,033 to 49,045 bytes**. The image-heavy synthetic study sheet decreased from **10,716,600 to 1,453,037 bytes** with study and **223,115 bytes** with compact. These figures describe these deliberately compressible synthetic fixtures, not promised ratios for arbitrary documents. Page count and normalized text were preserved. Before/after/diff renders were visually inspected; labels and vector lines remain legible. Processing reports still require human review and do not self-approve future output.

## Unexecuted gates and why

**Complete npm installation/inventory:** `npm ci --offline` lacks cached transitive packages (including util-deprecate). The separate offline helper restores checked-in JSZip/Prism entry points and uses already-installed exact TypeScript 5.8.3. This route builds/tests successfully, but is not a complete installed lockfile attestation. All inherited vendor bytes pass their original pins. Full transitive license/SBOM and current vulnerability checks remain uncompleted; no online audit was attempted.

**Normal-origin persistence:** managed Chromium rejects navigation to a local HTTP origin with `net::ERR_BLOCKED_BY_ADMINISTRATOR`. The production browser smoke and 13-case runtime suite therefore cannot certify IndexedDB writes, reload, secure-context crypto or browser backup/fresh-context restore. No policy was disabled and production security headers were not relaxed. DOM and actual Node ZIP tests are reported separately.

**Integrated PDF:** React-PDF/Vite/types packages are unavailable. Installed-module typecheck and integrated build fail at missing prerequisites; the 17-case PDF suite is BLOCKED. The build guard requires exactly React-PDF 10.5.0 / PDF.js 5.4.296 and all matching worker/CMaps/WASM/standard-font assets, but resource loading, physical modes, page controls, zoom/rotation/outline/search, password retry/cancel and corrupt recovery need a permitted real integrated run. The optional online installer resolves additional tooling on the coordinator's machine and writes an exact lockfile; that unexecuted installation is not represented as part of this fallback lockfile.

**Remote process:** branch location, remote CI, host preview/response verification and promotion belong to the coordinator. No repository, private PDF repo or deployment was created/changed. The supplied integration target is documented, not asserted as remotely verified.

## Privacy, preservation and handoff use

The original library under `09_PRIVATE_REFERENCE_LIBRARY_DO_NOT_PUBLISH/` was not imported or copied into source/build/evidence. Generated 137-page/685-term fixtures cover scale without its teaching prose; historical baseline audit summaries are clearly labelled history, not a new private-corpus test. Public output remains the exact reviewed starter: **8 pages, 2 projects and 1 glossary term**. Synthetic template PDFs are explicitly labelled ingestion fixtures and deliberately differ from built-in fixture bytes; no private user PDF is shipped. No credentials, installed dependencies or standalone font files are included.

To try the build, extract `AtlasNote_1.1_build.zip`, run `node serve.mjs` (or the Windows launcher) and open `http://127.0.0.1:4173`. Keep that origin stable. To rebuild offline, use a preinstalled TypeScript 5.8.3 with `npm run bootstrap:offline`, then `npm run build`. To prepare a private library, run the template validator/builder and import its generated ZIP locally. Keep source templates, evidence, private ZIPs and backups out of public static hosting.

The coordinator should integrate the source into `improvement/atlasnote-1.1-reader-pdf-library`, run normal-origin persistence and the optional integrated PDF matrix with real dependencies, review the pending license/security inventory and inspect a preview before promotion. This is the remaining release-gate boundary, not unfinished implementation replaced with a plan.
