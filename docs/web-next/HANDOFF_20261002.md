## 0. Owner decision — this is the important part

We are **returning AtlasNote to a Web-first direction**.

The Electron/Chromium DocPass experiment was useful, but it was the wrong product direction for Atlas because the owner values opening Atlas from any computer without installing a desktop application.

The target is therefore:

```
AtlasNote
React + Vite web app
Hosted on Cloudflare
Browser-local IndexedDB
Desktop-browser use first
```

Not:

```
Electron / DocPass
universal Chromium shell
Atlas + Norsk + CodeStudy hub
PowerToy / C# integration
Cloud Diagram integration
Jupyter / Marimo replacement
cross-device sync service
mobile handoff
```

Do not continue the DocPass architecture inside AtlasNote.

The old DocPass work exists separately in GitLab `julianpassebecq/docpass`. Treat it only as historical UX/engineering reference. Do not merge its storage/runtime architecture into AtlasNote.

## 2. What V3.1 already fixed

Do not throw these away.

### PDF / reading

V3.1 contains substantial PDF stabilization:

- page geometry is resolved before canvas mount;
- render completion no longer performs late scroll restoration;
- navigation/restoration has explicit document/page/geometry ownership tokens;
- stale restoration is cancelled;
- initial residual wheel consumption is bounded to geometry preparation, not rasterization;
- fast momentum keeps the one-turn burst guard;
- deliberate reverse input can reverse after cooldown;
- separated wheel detents can form a new edge intention;
- Continuous mode uses stable per-page estimates instead of a moving global average;
- newly resolved geometry compensates the visible anchor without undoing intervening user scrolling;
- navigation trace v2 records requested vs applied displacement and build identity;
- cancelled shared-cache loads do not leak orphan Blob URLs.

A previous real-device bug was also fixed before V3.1: with hidden reader chrome an unrendered previous page could collapse to a tiny loading height, then expand after paint and create a large visible jump. Keep that fix.

### IndexedDB / recovery / consistency

Keep:

- database `knowledge-atlas` version **3**;
- the same **five stores**;
- immutable history model;
- atomic current projection + history/review audit behavior;
- restore appends a new version rather than erasing history;
- all thirteen compaction rollback guarantees;
- verified backup replacement;
- restore from unreadable prior schema without silently resetting data;
- concurrent-change protection during restore;
- readiness after successful recovery;
- staged-hydration epoch detection;
- same-slot cross-tab checkpoint conflict handling.

Do not “fix” a test by clearing IndexedDB or changing database identity.

### Existing UX / product

AtlasNote already has:

- five logical subjects/workspaces;
- independent A/B panes;
- Notebook / notes;
- PDF;
- structured SVG cheatsheets;
- Article;
- QCM;
- content hub / library;
- search / references / history;
- Experience filtering;
- Norsk Daily;
- a small SVG Norwegian flag in the sidebar.

Code study belongs inside normal Atlas notes/code/cheatsheet workflows. Do not create a separate CodeStudy application.

## 5. Why the earlier assistant went off course

A previous conversation pivoted Atlas into a local Electron product called DocPass.

That experiment built:

- an Electron/Chromium shell;
- Atlas / Norsk / CodeStudy app tabs;
- local durable storage;
- native Chromium PDFs;
- later a two-app Atlas + Norsk simplification.

The owner then realized this loses a key benefit of Atlas: being a normal web application available on different computers.

Therefore **do not continue Electron**.

Useful ideas from that experiment may be reimplemented *inside the existing Web AtlasNote* only when they clearly improve the product, for example:

- cleaner Norsk bilingual reading;
- explicit import previews;
- better compact layouts;
- better search;
- preserving independent tab/pane state.

Do not copy the Electron storage model, desktop packaging, or app-shell complexity.

## 8. Data boundaries

Atlas remains browser-local first.

IndexedDB is the working data store. Backups remain the safety mechanism.

Changing Cloudflare origin / hostname creates a different browser origin and therefore a different IndexedDB namespace. Do not imply that deploying a new URL migrates user data.

Before any owner test on a different origin, tell the owner to export a full backup from the existing production origin.

Do not publish private backups, local PDFs, notes, interview material, or personal study content into the public source repository.
